# cli-roundtable: Cluster Networking Spec

## 1. Context & Motivation

**Current architecture:** cli-roundtable uses wg-easy (Docker container) as the WireGuard VPN control plane. Each host runs its own wg-easy, which manages peer registration, IP pool assignment, and config generation via its REST API.

**Problem:** wg-easy doesn't support clustering — each instance is isolated. You can't connect two wg-easy meshes together, and wg-easy's API doesn't expose `AllowedIPs` overrides needed for site-to-site routing.

**Decision:** Drop wg-easy. Replace with raw WireGuard (`wg-tools`) running natively on the host. This gives us full control over peer configs, eliminates container indirection (agent → host eth → docker bridge → wg-easy container → wg device → internet), and enables native host-to-host peering for clustering.

## 2. Architecture (Option C)

```
┌─────────────────────── HOST A ───────────────────────┐
│  wg0: 10.10.1.1/24 (host mesh IP)                    │
│  ├── agent-01 wg0: 10.10.1.2/32                      │
│  │    AllowedIPs: 10.0.0.0/8                          │
│  │    endpoint: host A lxbr0 IP :51821                │
│  ├── agent-02 wg0: 10.10.1.3/32                      │
│  │    AllowedIPs: 10.0.0.0/8                          │
│  │    endpoint: host A lxbr0 IP :51821                │
│  └── PEER: Host B                                     │
│       AllowedIPs: 10.20.1.0/24                        │
│       endpoint: <B-public-IP>:51820                   │
└───────────────────────────────────────────────────────┘

┌─────────────────────── HOST B ───────────────────────┐
│  wg0: 10.20.1.1/24 (host mesh IP)                    │
│  ├── agent-03 wg0: 10.20.1.2/32                      │
│  │    AllowedIPs: 10.0.0.0/8                          │
│  ├── agent-04 wg0: 10.20.1.3/32                      │
│  │    AllowedIPs: 10.0.0.0/8                          │
│  └── PEER: Host A                                     │
│       AllowedIPs: 10.10.1.0/24                        │
│       endpoint: <A-public-IP>:51820                   │
└───────────────────────────────────────────────────────┘
```

### Key design rules

1. **Agents are topology-agnostic.** Each agent's wg0 targets a single peer: its host. AllowedIPs = `CLUSTER_SUBNET` (default `10.0.0.0/8`). The agent never learns about remote hosts or subnets.
2. **Cluster topology lives on host wg0 only.** Host-to-host peer entries and AllowedIPs are the sole source of cross-cluster routing.
3. **Agent wg0 is configured once at creation** and never modified for networking. No config pushes when hosts join/leave the cluster.
4. **Two-layer WireGuard encryption is fine.** agent→host encrypts with agent key, host→remote re-encrypts with host key. WireGuard handles this natively.

### Packet flow: agent-01 → agent-04

1. agent-01 kernel: `10.20.1.3` matches `10.0.0.0/8` → wg0 → encrypts → host A via LXD bridge
2. host A wg0: decrypts → destination `10.20.1.3` → matches Host B peer (AllowedIPs `10.20.1.0/24`) → re-encrypts → internet
3. host B wg0: decrypts → source `10.10.1.2` in Host A's AllowedIPs → destination `10.20.1.3` → LXD bridge → agent-04
4. Return path reverses: agent-04 → host B → host A → agent-01

## 3. CLI Reference

### New commands

#### `roundtable wg init` — Initialize host WireGuard mesh

Creates `wg0` on the host with the configured subnet, generates host keys if absent, and brings the interface up.

```bash
roundtable wg init
# Reads: .env → WG_SUBNET, WG_PORT, WG_HOST (public IP/domain)
# Creates: /etc/wireguard/wg0.conf
# Creates: /var/lib/roundtable/  (state directory)
# Brings up: wg0
# Installs: systemd unit wg-quick@wg0 (enabled, started)
# Persists: host keypair at /etc/wireguard/ (auto-generated by wg-quick)
# Errors if: wg0 already exists (use --force to reconfigure)
```

Idempotent: safe to re-run (skips if already configured). `--force` tears down and re-creates.

#### `roundtable wg peer new <name>` — Create a WireGuard peer config for an agent

Generates a WireGuard config for a new agent peer. Assigns the next available IP from the pool. Produces the config file for injection into the agent container.

```bash
roundtable wg peer new arthur
# 1. Allocates next IP from pool: 10.10.1.2
# 2. Generates agent keypair (or accepts --pubkey/--privkey)
# 3. Adds peer entry to host /etc/wireguard/wg0.conf
# 4. Applies: wg set wg0 peer <pubkey> allowed-ips <agent-ip>/32
# 5. Prints agent's wg0.conf content to stdout
# 6. Records IP + name in /var/lib/roundtable/peers/
```

Output is an agent wg0.conf template:

```
[Interface]
Address = 10.10.1.2/32
PrivateKey = <agent-privkey>
DNS = 1.1.1.1

[Peer]
PublicKey = <host-pubkey>
AllowedIPs = ${CLUSTER_SUBNET:-10.0.0.0/8}
Endpoint = <lxbr0-ip>:${WG_PORT:-51820}
PersistentKeepalive = 25
```

The `${CLUSTER_SUBNET}` is a template variable — the actual value is resolved when the config is written into the agent container. This keeps `peer new` host-agnostic.

#### `roundtable wg peers` — List all peers (agents + cluster links)

Shows every peer on the host's wg0 — both local agents and connected remote meshes — in a single table.

```bash
roundtable wg peers
# NAME       IP           TYPE        STATUS
# arthur     10.10.1.2    agent       active
# horo       10.10.1.3    agent       active
# host-b     10.20.1.0/24 cluster     connected
```

- Agent peers show their individual IP (`10.10.1.2/32`)
- Cluster peers show the remote subnet (`10.20.1.0/24`)
- No sub-namespace needed — agents and clusters are just different `TYPE` values in the peer records

#### `roundtable wg peer config <name>` — Print a peer's WireGuard config

For agents: prints the agent wg0.conf content (with CLUSTER_SUBNET resolved). For cluster peers: prints the host-to-host config.

```bash
roundtable wg peer config arthur
# → agent wg0 config as installed
```

#### `roundtable wg peer rm <name>` — Remove a peer

Removes the peer from the host's wg0, frees the IP back to the pool, deletes the peer record.

```bash
roundtable wg peer rm arthur
# Removes from /etc/wireguard/wg0.conf
# wg set wg0 peer <pubkey> remove
# Frees IP in /var/lib/roundtable/ip-pool
# Removes from /var/lib/roundtable/peers/
```

#### `roundtable wg invite` — Generate an anonymous cluster invitation

**Stateless, zero arguments.** Dumps the host's connection details to stdout as an invite file. The invite can be sent to any remote host — there's no pending record or peer entry created locally.

```bash
roundtable wg invite > host-a.yml
# Reads: /etc/wireguard/publickey, .env → WG_HOST, WG_PORT, WG_SUBNET
# Prints: invite YAML to stdout
# No local state created
```

Invite file format:

```yaml
# wg invite — host-a
public_key: xTIB9q...J0Xk=
endpoint: 203.0.113.5:51820
subnet: 10.10.1.0/24
```

- `public_key`: The host's permanent wg0 public key (`/etc/wireguard/publickey`)
- `endpoint`: The host's public IP/domain and WireGuard port (from `WG_HOST` + `WG_PORT`)
- `subnet`: This host's mesh subnet (from `WG_SUBNET`) — the remote needs this to set `AllowedIPs`

Idempotent: safe to run any time. Same host = same pubkey/endpoint/subnet every invocation.

#### `roundtable wg join <name> <invite-file>` — Connect to a remote mesh

Consumes an invite file and adds the remote as a named cluster peer. The name is chosen locally — it's how you reference this peer in `leave` and see it in `wg peers`.

```bash
roundtable wg join host-b host-b.yml
# 1. Reads host-b.yml → extracts public_key, endpoint, subnet
# 2. Adds peer to host wg0:
#    wg set wg0 peer <remote-pubkey> allowed-ips <subnet> endpoint <endpoint>
# 3. Persists peer record at /var/lib/roundtable/peers/host-b.conf
# 4. Writes remote subnet to /var/lib/roundtable/cluster-subnets
# 5. Prints: "Joined cluster peer \"host-b\" — one-way until host-b reciprocates"
```

Cluster joins are **one-way until reciprocated**. After `join`, this host can reach the remote subnet, but the remote can't reach back until it also runs `join` with this host's invite. The command prints a reminder to share your own invite.

#### `roundtable wg leave <name>` — Disconnect from a remote mesh

Removes the named cluster peer from wg0 and from the state directory. Only affects the local side — the remote host still has you as a peer until it also runs `leave`.

```bash
roundtable wg leave host-b
# 1. Read peer record from /var/lib/roundtable/peers/host-b.conf
# 2. wg set wg0 peer <pubkey> remove
# 3. Removes /var/lib/roundtable/peers/host-b.conf
# 4. Removes subnet from /var/lib/roundtable/cluster-subnets
# 5. Prints: "Removed cluster peer \"host-b\"" 
```

#### `roundtable wg down` (modified) — Tear down wg0

Existing command, unchanged semantics. Destroys wg0, stops wg-quick service. Does NOT remove peer records or pool state — wg init + wg up restores them.

#### `roundtable wg up` (modified) — Bring up wg0

Existing command, unchanged semantics. Brings wg0 up. Remaining peers and cluster links are re-established from state files.

### Commands that change semantics

| Old command (wg-easy) | New command (raw-wg) | Change |
|---|---|---|
| `wg peer new` | `wg peer new` same name | Backed by file pool instead of API |
| `wg peer list` | `wg peers` | Merged agents + cluster peers in one listing |
| `wg peer config` | `wg peer config` same name | Local file read instead of API call |
| `wg host up` | `wg init` | Different: creates host's own wg interface, not a wg-easy client |
| `wg host down` | `wg down` | Same — tears down wg0 |
| `wg host ip` | (removed) | Obsolete, host IP is `WG_SUBNET .1` |
| (none) | `wg invite` | New — anonymous stateless invite generation |
| (none) | `wg join` | New — consume invite, add cluster peer |
| (none) | `wg leave` | New — remove cluster peer by name |
| `wg logs` | (removed) | Obsolete (no wg-easy container) |
| `wg up` (start wg-easy) | `wg up` (start wg0) | Changed: start host wg0 |

### `agent create` (modified)

Agent creation updates:
1. Calls `roundtable wg peer new <name>` to allocate IP + generate config
2. Stores the generated agent wg0.conf under `.agents/<name>/wg0.conf`
3. On container clone: injects wg0.conf into `/etc/wireguard/wg0.conf` inside the container
4. Starts `wg-quick up wg0` inside the container

No change to the golden image build — WireGuard tools are already installed.

### `agent delete` (modified)

Agent deletion updates:
1. Calls `roundtable wg peer rm <name>` to free the IP and remove peer
2. Removes `.agents/<name>/wg0.conf`

## 4. Configuration (YAML via yq)

Configuration is stored in `.roundtable/config` (YAML format) in the project root, parsed via `mikefarah/yq` v4.44.6 (Go binary). The config tree:

```yaml
network:
  host: vps-ip-or-domain              # Public IP/domain (required)
  wg:
    interface: wg0                     # WireGuard interface name
    port: 51820                        # Listen port
    subnets:
      cluster: 10.0.0.0/8             # Agent routing scope (AllowedIPs)
      agents: 10.0.1.0/24             # Local agent IP pool (host .1, pool .2-.254)
      foreign: 10.0.2.0/24            # Admin/laptop VPN peer range
    opts:
      persistent_keepalive: 25        # Keepalive interval (seconds)
agents:
  limits:
    cpu: 1
    memory: 768MB
golden-image:
  base: ubuntu:24.04
```

### Config values

| YAML path | Variable | Default | Purpose |
|-----------|----------|---------|---------|
| `network.host` | `WG_HOST` | (required) | Public IP or domain (needed for cluster invites) |
| `network.wg.interface` | `WG_INTERFACE` | `wg0` | WireGuard interface name |
| `network.wg.port` | `WG_PORT` | `51820` | WireGuard listen port |
| `network.wg.subnets.cluster` | `CLUSTER_SUBNET` | `10.0.0.0/8` | The cluster-wide network prefix agents route through their host |
| `network.wg.subnets.agents` | `AGENTS_SUBNET` | `10.0.1.0/24` | Local agent IP pool (host mesh IP = .1) |
| `network.wg.subnets.foreign` | `FOREIGN_SUBNET` | `10.0.2.0/24` | Admin/laptop VPN peer range |
| `network.wg.opts.persistent_keepalive` | `PERSISTENT_KEEPALIVE` | `25` | Keepalive interval for agent→host and cluster links |
| `agents.limits.cpu` | `AGENT_CPU` | `1` | vCPU limit per agent |
| `agents.limits.memory` | `AGENT_MEMORY` | `768MB` | RAM limit per agent |
| `golden-image.base` | `UBUNTU_IMAGE` | `ubuntu:24.04` | LXD image for golden image base |

### Removed (from .env)

| Variable | Why |
|----------|-----|
| `WG_PASSWORD` | wg-easy eliminated |
| `WG_PASSWORD_HASH` | Same |
| `WG_HOST_IP` | wg-easy static IP not needed |
| `WG_POOL_ADDRESS` | Handled by IP pool allocator |
| `WG_ALLOWED_IPS` | Per-agent = CLUSTER_SUBNET, per-host = joined subnets |
| `WG_EASY_VERSION` | No wg-easy |
| `WG_TOOLS_VER`, `CURL_VER`, `CA_CERT_VER` | Replaced by apt in golden image build |

## 5. State Directory: `.roundtable/`

```
cli-roundtable/
└── .roundtable/             ← State directory (gitignored, auto-created by wg init)
    ├── config               ← YAML config (copy from config.example, edit)
    ├── ip-pool              ← Flat file, one IP per line, "#" for allocated
    ├── cluster-subnets      ← One subnet per line (e.g. "10.0.1.0/24")
    └── peers/               ← Peer records (YAML format)
        ├── arthur.yml       ← Agent peer record
        └── host-b.yml       ← Cluster peer record
```

### `ip-pool` format

```
# Auto-generated by roundtable. Do not edit manually.
# Available IPs above allocated IPs.
10.10.1.2
10.10.1.3
10.10.1.4
#10.10.1.5      ← "#" prefix means allocated
10.10.1.6
#10.10.1.7
10.10.1.8
...
10.10.1.254
```

Allocation algorithm: scan for first line without `#` prefix, read the IP, prepend `#`. Deallocation: remove `#` prefix.

### `peers/<name>.yml` format (agent)

```yaml
# .roundtable/peers/arthur.yml
name: arthur
ip: 10.0.1.2
public_key: xTIB9q...J0Xk=
type: agent
created: 2026-06-21T12:00:00Z
```

### `peers/<name>.yml` format (cluster)

```yaml
# .roundtable/peers/host-b.yml
name: host-b
type: cluster
public_key: <remote-host-public-key>
endpoint: 203.0.113.5:51820
subnets:
  agents: 10.0.3.0/24
  foreign: 10.0.4.0/24
created: 2026-06-21T12:00:00Z
```

## 6. Implementation plan

### Phase 1: Core host WireGuard (`roundtable wg init`, `wg up`, `wg down`)

Replace wg-easy Docker setup with host-level wg0. No agents yet — just the host mesh interface.

**Files to create/modify:**
- `cmd_wg_init()` — new function in `roundtable`
- `cmd_wg_up()` — reworked (was `docker compose up wg-easy`, now `wg-quick up wg0`)
- `cmd_wg_down()` — reworked (was `docker compose down`, now `wg-quick down wg0`)
- State directory creation (`/var/lib/roundtable/`)
- Systemd service for wg0 persistence

**Validation:**
- `sudo wg show wg0` shows interface up with listen port
- `ping <host-ip>` from another machine's WireGuard client works

### Phase 2: Agent peer management (`wg peer new`, `peer ls`, `peer config`, `peer rm`)

File-based IP pool + peer record management. Generate agent WireGuard configs.

**Files to create/modify:**
- `cmd_wg_peer()` subcommand dispatch (unchanged architecture)
- `cmd_wg_peer_new()` — allocate IP, generate keys, add host peer, print config
- `cmd_wg_peer_ls()` — read `/var/lib/roundtable/peers/`
- `cmd_wg_peer_config()` — resolve CLUSTER_SUBNET into agent config and print
- `cmd_wg_peer_rm()` — remove peer from host wg0, free IP, delete record

**Key generation:** Use `wg genkey | tee /dev/stderr | wg pubkey` — two options:
- `roundtable wg peer new name` → auto-generates
- `roundtable wg peer new name --pubkey <base64>` → accepts existing key (for restore)

**Validation:**
- `roundtable wg peer new test-agent` prints valid WireGuard config
- `wg show wg0` shows the new peer
- `roundtable wg peer ls` shows test-agent
- `roundtable wg peer rm test-agent` removes it
- `roundtable wg peer new test-agent` re-uses the freed IP

### Phase 3: Cluster peering (`wg invite`, `wg join`, `wg leave`, `wg peers`)

Host-to-host peering via invite files. No SSH dependency — config files are the transport.

**Files to create/modify:**
- `cmd_wg_invite()` — read pubkey + .env, print YAML to stdout (stateless)
- `cmd_wg_join()` — consume invite YAML, add peer to wg0, persist record, update cluster-subnets
- `cmd_wg_leave()` — remove peer from wg0, delete record, remove from cluster-subnets
- `cmd_wg_peers()` — read all peer records (agents + cluster), print table
- Invite file parser (YAML or source it as shell vars)

**Key design considerations:**
- `invite` creates zero local state — safe to run any time
- `join` prints a reminder to reciprocate: "One-way until <name> also joins with your invite"
- `leave` is local-only — the remote still has you as a peer until it runs `leave` too
- Subnet overlap warning when joining: if the incoming subnet overlaps `WG_SUBNET` or any existing cluster subnet, print a warning (not fatal)

**Validation:**
- `roundtable wg invite > a.yml` prints valid YAML with pubkey, endpoint, subnet
- `roundtable wg invite > a.yml && roundtable wg invite > a2.yml` produces identical output
- Copy `a.yml` to Host B; `roundtable wg join host-a a.yml` adds peer, persists record
- `roundtable wg peers` shows the cluster peer
- `roundtable wg leave host-a` removes it, wg0 no longer shows the peer

**End-to-end cluster test (two VPS instances):**
```
Host A: roundtable wg invite > host-a.yml
Host B: roundtable wg invite > host-b.yml
(scp invites to each other)
Host A: roundtable wg join host-b host-b.yml
Host B: roundtable wg join host-a host-a.yml
→ ping 10.20.1.1 from Host A succeeds
→ ping 10.10.1.1 from Host B succeeds
```

### Phase 4: Agent integration (`agent create`, `agent delete`)

Wire the new peer management into the agent lifecycle.

**Files to modify:**
- `cmd_agent_create()` — call `wg peer new` internally, store config in `.agents/<name>/`
- `cmd_agent_delete()` — call `wg peer rm` internally
- Agent container provisioning — inject `.agents/<name>/wg0.conf` into container and `wg-quick up wg0`

**Validation:**
- `roundtable agent create arthur` → container created, wg0 config injected, peer listed on host
- `wg show wg0` shows agent peer
- From another mesh-connected host: `ping 10.10.1.2` reaches agent inside container
- `roundtable agent delete arthur` → peer removed, IP freed, container destroyed

### Phase 5: Migration path (wg-easy → raw wg)

One-time migration command for existing deployments.

```
roundtable wg migrate
# 1. Reads current wg-easy peers via API
# 2. For each agent peer:
#    a. Creates record in /var/lib/roundtable/peers/
#    b. Allocates IP in /var/lib/roundtable/ip-pool
#    c. Exports public key from container or stored config
#    d. Imports into /etc/wireguard/wg0.conf
# 3. Stops wg-easy container
# 4. Starts host wg0 (wg-quick up wg0)
# 5. Prints summary of migrated peers
```

**Edge case:** Agent configs need updating — their wg0.conf `Endpoint` changes from wg-easy Docker IP to host LXD bridge IP. The agent's `AllowedIPs` also needs to be widened from the single `/32` to `CLUSTER_SUBNET`. The migration CLI handles this by generating updated configs for each agent and printing the command to inject them.

## 7. Edge cases & error handling

### Subnet overlap detection

When joining a cluster, verify the remote subnet doesn't overlap with the local subnet. Use `ipcalc` or `grep -c` + CIDR math:

```bash
# Check overlap: remote_subnet=10.10.1.0/24, local_subnet=10.10.2.0/24
# Want: do they intersect?
# Simple check: same /16 prefix? → potential overlap
# Better: use `ipcalc` to check intersection
if [[ "$(echo "$LOCAL_SUBNET" | cut -d. -f1-2)" == "$(echo "$REMOTE_SUBNET" | cut -d. -f1-2)" ]]; then
    warn "Subnets overlap — verify they don't intersect"
fi
```

For now, warn only (not fatal) — the operator should know what they're doing. Full CIDR intersection detection (`ipcalc $REMOTE_SUBNET 2>&1 | grep -q "$LOCAL_SUBNET"`) is a nice-to-have.

### Agent loses wg0 config

`agent create` stores the agent wg0.conf in `.agents/<name>/wg0.conf` on the host. If the agent container's config is lost (filesystem corruption), regenerate:

```bash
roundtable wg peer config arthur | ssh arthur "cat > /etc/wireguard/wg0.conf"
roundtable agent exec arthur "wg-quick up wg0"
```

### Host key rotation

If a host's WireGuard private key changes (compromise, migration), every peer entry on other hosts and every agent's wg0 config must be updated.

```bash
roundtable wg init --rotate-key
# 1. Generates new host keypair
# 2. Broadcasts new pubkey to all:
#    a. Local agents (injected via LXD file push)
#    b. Remote cluster hosts (SSH push if configured)
# 3. Updates /etc/wireguard/
```

This is a separate command from init. Not needed for initial implementation but the architecture should support it.

### Host reboot

`wg-quick@wg0` is a systemd service with `WantedBy=multi-user.target`. On reboot, the host wg0 comes up automatically, all peer entries (agents + cluster links) are restored from config file. No state loss.

### Agent reboot

Agent containers have `wg-quick up wg0` in their startup (or a systemd unit). Config persisted at `/etc/wireguard/wg0.conf`. On reboot, agent reconnects to host wg0. No state loss.

### Firewall rules

Host must allow `WG_PORT/udp` inbound. `roundtable wg init` should check and warn if not open (via `ufw status` or `iptables -L` check).

No special iptables rules needed for forwarding if `net.ipv4.ip_forward=1` is enabled (already required for LXD). WireGuard routes through the host kernel naturally.

### Agent isolation

An agent can only reach IPs that match its `AllowedIPs` = `CLUSTER_SUBNET`. It cannot reach the host's LAN, internet-facing eth0, or Docker networks. Traffic to non-`10.x.x.x` IPs goes through eth0 as normal. If the agent needs both cluster access and internet, both routes exist (eth0 for internet, wg0 for cluster) — the kernel picks based on the destination IP.
